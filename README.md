# Add Product

A product list with pagination stored in the URL, plus a three-step "Add product" form in a dialog. The UI follows the Figma design, including the mobile layout.

- **Repository:** [https://github.com/Lukols-Dev/next16-tanstackForm-shadcn](https://github.com/Lukols-Dev/next16-tanstackForm-shadcn)
- **Live demo:**

## Features

- **Product table** - 7 seed products (mock data), 5 per page. Columns: name, SKU, category, gross price with currency, availability status, stock level.
- **Pagination in the URL** - the page number lives in `?page=` (nuqs). Reloading the page keeps the view, and an invalid page number (`?page=0`, `?page=999`, `?page=abc`) is clamped to the existing range.
- **"Add product" dialog** - three steps: basic information, price, availability.
  - live validation with error messages next to the fields,
  - "Next" only advances when the step is valid; otherwise it shows all of the step's errors and moves focus to the first invalid field,
  - "Back" keeps the entered values,
  - net and gross prices are recalculated from each other using the VAT rate,
  - every way of closing the dialog (X, Escape, clicking the backdrop, saving) resets the form to step 1.
- **After saving** the product is appended to the end of the list, the view stays on the current page, and a "Produkt został dodany" notification appears.
- **Responsive layout** - below 1024 px the table turns into a list of cards, and below 768 px the dialog opens full screen.

## Getting started

**Requirements:** Node.js 22.22+ or 24.15+, pnpm (e.g. via `corepack enable`). The app alone runs on Node.js 20.9+, but the test tools (Vitest 5, jsdom 30) need a newer version.

```bash
git clone https://github.com/Lukols-Dev/next16-tanstackForm-shadcn.git
cd next16-tanstackForm-shadcn
pnpm install
pnpm dev
```

The app runs at [http://localhost:3000](http://localhost:3000).

### Tests

The tests use Vitest with React Testing Library in jsdom, so they need neither a browser nor a running server. After `pnpm install`:

```bash
pnpm test                               # run the whole suite once
pnpm exec vitest                        # watch mode: re-runs tests on file changes
pnpm exec vitest run features/products  # only test files whose path matches
```

Test files sit next to the code they cover (`*.test.ts`, `*.test.tsx`). The configuration is in `vitest.config.mts` and `vitest.setup.ts`.

## Project structure

The code is organized by feature (feature-first): everything related to products lives in one module, and the shared layers are kept separate from it.

```
app/                        routing: layout, home page, global styles and color tokens
providers/                  app providers (nuqs, notifications)
messages/                   all UI copy and error messages (in Polish)
lib/                        general utilities: locale, plural forms, cn()
components/
  ui/                       shadcn/ui components (generated by the CLI)
  form/                     TanStack Form wired to shadcn components - typed form fields
entities/product/           product domain model
  model/                    value catalogs (categories, manufacturers, features, VAT, currencies) and the product schema
  lib/                      price formatting, net ↔ gross conversion
  ui/                       availability status, stock level
features/products/          the "products" feature - publicly exports only ProductsView
  data/                     mock data
  model/                    page size, pagination logic
  hooks/                    page number in the URL (nuqs)
  ui/                       list view: header, table, mobile cards, pagination
  add-product/              add-product wizard
    model/                  steps, default values, Zod schemas per step, form-to-product mapping
    ui/                     dialog, wizard, stepper, footer, steps
```

## Key decisions

**Form and validation**

- A single form instance (`useAppForm`) handles all three steps, so values are not lost when going back.
- Each step is a `form.FormGroup` with its own Zod schema as the validator. "Next" validates the group: on failure it marks all of the step's fields as touched, so the messages appear at once. The shared `StepForm` component handles submitting a step and moving focus to the first invalid field.
- Rules that depend on several fields (stock quantity required only for a limited product, minimum ≤ maximum) live in `superRefine` and attach the error to a specific field.
- An empty select or number field holds `null`, not `""` or `0` - so "nothing selected" and "entered 0" are different states.
- Before saving, the form values go through the product schema (`toProduct`), so only a complete, valid object is added to the list.
- SKU is checked for uniqueness among existing products.

**Prices**

- Net ↔ gross conversion happens in field listeners, not in `useEffect` - changing one field updates the other without a loop.
- Changing the VAT rate recalculates the gross price from the net price. Amounts are rounded to the cent.
- Price fields use the design's format, the same as the "0.00" placeholder. A comma typed on a Polish keyboard is accepted as the decimal separator.

**Dialog**

- The dialog content unmounts on close, so every opening starts with a clean form on step 1.
- The stepper announces the current step to screen readers (`aria-current`, a "Krok 2 z 3" message).

**List and pagination**

- The component that reads the page number from the URL is wrapped in `<Suspense>`, so the header with the product count is included in the static HTML right away.

**UI copy**

- All copy lives in `messages/`, and the app language is set in one place (`lib/locale.ts`) - it drives `<html lang>`, price formatting and plural forms.

## Limitations

- No backend: products are kept in browser memory. After a page reload the list goes back to the seed data, while the page number from the URL is preserved.
